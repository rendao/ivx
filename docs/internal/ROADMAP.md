# IVX Roadmap

## 1. Context
This file is the rolling product roadmap record for IVX.

It tracks medium-term direction and phase outcomes, and should be updated continuously instead of creating only date-stamped strategy files.

## 2. Scope
In scope:
- product evolution phases and objectives
- measurable expected outcomes
- phase entry/exit criteria

Out of scope:
- sprint-level implementation tasks
- per-session execution details

## 3. Decision or Plan
### Phase A: Data Trust Hardening (Current Priority)
Objectives:
- maximize confidence of metrics used for operational decisions
- reduce stale or ambiguous governance/testing signals

Expected outcomes:
- stronger traceability coverage
- lower payload/contract error rate
- stable health diagnostics across runtime and state files

Exit criteria:
- data quality tier is consistently A/B for active projects
- major decision metrics are reproducible from artifact/event evidence

### Phase B: Action-Loop Productization
Objectives:
- convert passive status views into action-driving workflows
- reduce unresolved intervention backlog and resolution lead time

Expected outcomes:
- each intervention item has owner/priority/due/status/next action
- recommendation rules map common risk patterns to clear actions

Exit criteria:
- intervention resolution lead time shows sustained reduction
- pending intervention backlog trend is controlled

### Phase C: Multi-Project Operating Model
Objectives:
- support comparable governance and delivery views across projects
- make adoption low-friction and non-invasive

Expected outcomes:
- second-project onboarding playbook validated
- portfolio baseline comparison available

Exit criteria:
- at least two projects can produce reproducible comparable metrics
- rollout checklist and operating runbook are stable

## 4. Acceptance Criteria
- Roadmap phases are clear, measurable, and ordered.
- Every phase has explicit entry/exit criteria.
- This file can be used as the single source for medium-term product direction.

## 5. Risks and Rollback
Risk 1: over-indexing on features before data trust.
- Rollback: freeze work to Phase A constraints until evidence confidence is stable.

Risk 2: roadmap drift from implementation reality.
- Rollback: synchronize with PLAN.md at least once per week.
